增量还是重建？（本系统的决策规则，构建日志中可见实际选择）

  • 安全增量：批次只带来成品需求（新“成品+日期”对，或需求数量变化）。需求是加性事实， 不影响其他需求对的展开结果 → 只展开这些需求对，其余原样沿用。
  • 必须重建：结构更正（用量/生效区间/父子关系）或替代优先级变化。数量沿路径连乘、 共享子件跨成品聚合，局部打补丁不可靠 → 受影响范围 = 变更父节点的祖先锥 （按全部历史边取保守超集）∩ 已有需求。
  • 局部重建 vs 全量：祖先锥外的需求对原样沿用（partial）；锥覆盖全部需求对或手动指定 → full。
  • 重叠构建：版本号单调分配，发布是单条带守卫的原子 UPDATE（版本更大且基线批次不更小才生效）， 晚完成的旧构建被拒绝（stale），已发布版本不会回退。
  • 读者一致性：读者只读“已发布”这一份快照，快照行不可变 → 不会看到一半新结构一半旧数量。
  • 环路：只在当前路径上检测并截断（标记“环路截断”），其余路径正常展开，仓库整体可查。
