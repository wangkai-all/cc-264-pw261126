# bomwh — 带生效日期与替代关系的物料结构仓库

把**带生效日期和替代关系的物料结构**入仓（SQLite），支持按“成品 + 日期”查询**多层需求与来源路径**，
并对结构更正、替代优先级变化、成品需求的混合到达做出**增量 / 局部重建 / 全量重建**决策，
以**版本化快照 + 原子发布**保证并发构建不回退、读者不见半成品。

纯 Python 3 标准库实现，无第三方依赖。

## 快速开始

```bash
python run.py init                 # 初始化仓库（默认 data/bom.db）
python run.py ingest b1            # 接入样例批次 b1（基础结构+需求）
python run.py build                # 构建并发布快照（auto 决策）
python run.py explode F1 --date 2026-03-01 --qty 10   # 查快照
python run.py explode F2 --date 2026-03-01 --qty 5 --live  # 实时重算
python run.py serve --port 8000    # 网页：http://localhost:8000
python demo.py                     # 无浏览器全流程演示（含重叠构建/中止，带断言）
python -m unittest discover -s tests   # 19 个测试
```

网页上可完成全部操作：载入样例批次（b1→b4、stress）、触发构建（可调慢速）、
中止构建、查询多层需求（快照/实时两种模式），并查看每次构建的决策说明。

## 数据模型（双时间维度）

| 表 | 作用 |
|---|---|
| `edges` | 结构版本：父件→子件、单位用量、生效区间 `[eff_from, eff_to)`、替代槽位 |
| `slot_members` | 替代槽位成员：同槽位按优先级（数值小者优先）挑子件 |
| `demands` | 成品需求（产品、数量、需求日期） |
| `batches` | 接入批次（事务时间），一批可混合携带结构/更正/替代/需求 |
| `snapshots` + `req_rows` | 派生快照：一次构建一份，行不可变 |
| `published` | 单行发布指针，原子切换 |

- **业务时间**：`eff_from/eff_to`，回答“哪一天结构是什么”；
- **事务时间**：`batch_id` / `superseded_by`，回答“哪个批次知道这件事”；
- **更正不修改旧行**：旧行标记 `superseded_by`，更正行自带生效区间；只覆盖部分区间时
  自动拆出前段/后段剩余行（`kind='remainder'`），任一日期解析结果唯一。
  追溯更正（生效日倒签）因此天然成立：历史查询日期也用新值。

## 展开语义（bomwh/explode.py）

- 数量沿路径连乘：`required(child) = required(parent) × qty_per`；
- **共享子件不漏乘**：不用全局访问集，每条路径独立展开各自连乘，汇总再相加
  （样例：C 经 F1/A/C、F1/B/C、F1/S/C 三条路径 = 60+40+50 = 150）；
- **环路按路径隔离**：只在当前路径（祖先栈）上检测，命中即截断该路径并打
  `cycle` 标记（数量为下限），其余路径照常展开，仓库整体可查；
- **替代解析**：查询日期上取优先级最高的生效槽位成员，命中非默认子件时标记
  `via_substitute`；每行记录 `edge_ids`（来源结构版本）与完整路径，可溯源。

## 增量还是重建？（bomwh/derive.py）

批次到达后**不在接入时展开**，构建时按变更分类决策（决策理由写入快照 `note`，页面可见）：

| 变更 | 决策 | 理由 |
|---|---|---|
| 新成品需求 / 需求数量变化 | **安全增量**（incremental） | 需求是加性事实，不影响其他需求对的展开结果 → 只展开这些需求对，其余原样沿用 |
| 结构更正（用量/区间/父子） | **必须重建** | 数量连乘 + 共享子件跨成品聚合，局部补丁不可靠 |
| 替代优先级变化 | **必须重建** | 波及使用该槽位的所有父件的祖先锥 |

重建范围：受影响集合 = 变更父节点的**祖先锥**（沿**全部历史边**向上取保守超集，
保证删边/改边后锥只大不小）∩ 已有需求。锥外需求对行级复制沿用 → **局部重建（partial）**；
锥覆盖全部需求对或手动指定 → **全量重建（full）**。
样例：b2（混合批次，锥={F1,F2,S}）→ full；b3（纯需求）→ incremental；
b4（只波及 F2）→ partial。

## 并发与发布

- 每次构建写独立 `snapshot_id` 的行；**展开阶段只读**（行缓冲内存），
  落行 + 沿用复制 + 发布合并在**最后一个短事务**里；
- 版本号构建开始时单调分配；发布是单条带守卫的 `UPDATE`：
  `version` 更大 **且** `base_batch` 不更小才生效 —— 重叠构建中晚完成的旧构建
  被拒绝（`stale`），**已发布版本不回退**；
- 读者先读发布指针、再读该快照的行，快照行不可变 → **不会看到一半新结构一半旧数量**；
- 构建可中止：状态 `aborted`、清理未发布行，已发布版本无感知。

## 样例批次（bomwh/samples.py）

- **b1**：多父节点（F1、F2 共用 S）、菱形共享（A→C、B→C）、跨层共享（S→C）、
  替代槽位（P 主选 / P2 备选）、X↔Y 环路、两个成品需求；
- **b2**：追溯更正（F1→A 2→3，生效日倒签）+ 替代优先级翻转（P2 升最优）+
  新需求，同批到达 → 决策为全量重建；
- **b3**：纯需求批次 → 安全增量；
- **b4**：前向更正（F2→C 7→8 自 2026-07-01）→ 局部重建 + 生效区间拆分
  （同一成品不同日期解析到不同用量）；
- **stress**：60 件三叉树 + 10 个需求对，配合 `--slow` 演示慢构建、中止与重叠重建。

## 目录

```
bomwh/
  db.py       模式与连接（双时间维度、快照、发布指针）
  ingest.py   批次化接入；更正拆分，历史行不可变
  explode.py  递归展开：连乘、替代解析、环路按路径隔离
  derive.py   变更分类 → 增量/局部/全量决策 → 构建 → 原子发布
  samples.py  样例批次
  server.py   HTTP API（仅标准库）
  web/index.html  查询页面
run.py        CLI；demo.py 全流程演示；tests/ 19 个测试
```
